## 발견된 비용 문제 (리소스별 상세)

### RDS 인스턴스 과도한 프로비저닝
- **개발 환경 Multi-AZ 불필요 사용**: 개발 환경 RDS 인스턴스 2개(db-instance-n2mzkv, db-instance-5iydcw)에서 Multi-AZ가 활성화되어 있으나 개발 용도로는 고가용성이 불필요
- **낮은 CPU 사용률**: 두 개발 DB 모두 평균 CPU 사용률 15% 수준으로 충분한 여유 자원 보유
- **프로덕션과 동일한 구성**: 개발 환경이 프로덕션(db-instance-g7mz7s)과 동일한 db.r5.large + Multi-AZ 구성 사용

### 예약 인스턴스 미활용
- **온디맨드 요금제**: 월 $2,953의 안정적인 비용 패턴에도 불구하고 예약 인스턴스 미사용
- **예측 가능한 워크로드**: 3개월간 일관된 사용 패턴으로 예약 인스턴스 적용에 적합

## 근본 원인 분석

### 환경별 차별화 정책 부재
개발 환경과 프로덕션 환경의 요구사항이 다름에도 불구하고 동일한 인프라 구성을 적용하여 비용 효율성을 고려하지 못했습니다.

### 비용 최적화 전략 부족
안정적인 워크로드 패턴에 적합한 예약 인스턴스 활용 전략이 수립되지 않아 온디맨드 요금제의 높은 비용을 지속적으로 지불하고 있습니다.

### 리소스 모니터링 체계 미흡
 CPU 사용률 등 실제 사용량 대비 프로비저닝된 자원의 적정성을 정기적으로 검토하는 체계가 부족했습니다.

## 개선 방안 (우선순위 순)

### 1순위: 개발 환경 Multi-AZ 비활성화
- **대상**: db-instance-n2mzkv, db-instance-5iydcw
- **작업**: `multi_az = false`로 변경
- **즉시 적용 가능**: 다운타임 발생하지만 개발 환경이므로 영향 최소

### 2순위: 예약 인스턴스 구매
- **대상**: 3개 RDS 인스턴스 모두 (db.r5.large)
- **옵션**: 1년 약정, 부분 선결제
- **안정적 사용 패턴**: 3개월간 일관된 월 $2,953 비용으로 예측 가능

### 3순위: 개발 환경 인스턴스 타입 검토
- **현재**: db.r5.large (CPU 15% 사용률)
- **검토 대상**: db.t3.large 또는 db.t3.medium으로 다운사이징
- **추가 검증 필요**: 성능 테스트 후 적용

### 4순위: 환경별 정책 수립
- **개발 환경 가이드라인**: Single-AZ, 버스터블 인스턴스 타입 우선
- **비용 모니터링**: 월간 사용률 및 비용 효율성 검토 프로세스 구축
