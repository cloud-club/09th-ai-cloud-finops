## 문제 발견

### 비효율 리소스

3개 Lambda 함수에 3008MB가 할당되어 있으나 30일간 720개 측정 포인트 전 구간에서 실사용량이 100MB로 고정됨.

| 함수 | 설정 메모리 | 실사용 | 이용률 | 절감액 |
|------|------------|--------|--------|--------|
| lambda-function-oycs3i | 3008MB | ~100MB | 3.3% | $250/mo |
| lambda-function-fl3urm | 3008MB | ~100MB | 3.3% | $250/mo |
| lambda-function-63wtbt | 3008MB | ~100MB | 3.3% | $250/mo |
| lambda-function-v17j3o | 512MB | ~100MB | 19.5% | 정상 |
| lambda-function-jepj6c | 512MB | ~100MB | 19.5% | 정상 |

### 근본 원인

Lambda 함수가 초기 배포 시 과도하게 큰 메모리로 설정된 채 검토 없이 운영됨. Lambda는 GB-초 단위 과금이므로 미사용 메모리(2908MB)도 전액 과금된다. 동일 환경에서 512MB 함수 2개(v17j3o, jepj6c)가 정상 동작하는 것이 적정 메모리 크기의 근거.

### 증거

- configured=3008MB, actual_usage_mean=100MB (720포인트 전 구간 고정), 이용률=3.3%
- 비효율 3함수의 GB-초 비중: 3×3008 = 9024 units / 전체 10048 units = 89.81%
- 6개월 Lambda 월평균 $1001.71 (총비용 $4557.87의 22.0%)
- 메모리 축소 절감률: 1 - (512/3008) = 82.98% per function

## 절감액 계산

Lambda 요금 공식: `$0.0000166667 / GB-second`

```
3008MB → 512MB 절감률 = 1 - (512/3008) = 82.98%
3함수 GB-초 비중 = 9024 / 10048 = 89.81%
3함수 월비용 = $1001.71 × 89.81% = $899.62
3함수 절감액 = $899.62 × 82.98% = $746.49 ≈ $750/mo
함수당 절감 = $750 / 3 = $250/mo
```

## 권장 조치

1. **즉시 적용**: `memory_size = 3008` → `memory_size = 512` 변경 후 `terraform apply`
2. **모니터링**: CloudWatch Logs Insights로 실측 메모리 모니터링, 80% 초과 시 경고 알람
3. **정기 검토**: AWS Lambda Power Tuning 도구로 주기적 메모리 최적화 검증
