# L1-010 비용 분석 보고서 — TrackPulse (물류/배송)

## 1. 문제 식별

### DynamoDB 테이블 `dynamodb-table-mnrimh` — 심각한 과다 프로비저닝

| 항목 | 프로비저닝 용량 | 실제 사용량 (최대) | 사용률 |
|------|----------------|-------------------|--------|
| Read Capacity Units (RCU) | 5,000 | 100 | **2%** |
| Write Capacity Units (WCU) | 1,000 | 100 | **10%** |

- RCU는 프로비저닝의 **2%만 사용**, WCU는 **10%만 사용**
- 30일간 사용량이 안정적(stable trend, 표준편차 ≈ 0)으로 피크 트래픽도 100을 초과하지 않음
- 4,900 RCU와 900 WCU가 완전히 낭비되고 있음

### DynamoDB 테이블 `dynamodb-table-wt6cp5` — 과금 모드 비효율

- 현재 `PAY_PER_REQUEST` (온디맨드) 모드 사용
- 사용량: RCU 100, WCU 100으로 **완전히 일정** (std=0, trend=stable)
- 안정적인 워크로드에 온디맨드 모드는 프로비저닝 대비 **약 5~7배 비쌈**

## 2. 근본 원인 분석

### `dynamodb-table-mnrimh`
- 초기 트래픽 예측 과다 또는 피크 대비 과잉 설계로 인한 레거시 설정
- Auto Scaling 미적용 — 고정 프로비저닝으로 유지 중
- FinOps 팀이 생겼지만 기존 설정에 대한 리뷰가 아직 이루어지지 않은 상태

### `dynamodb-table-wt6cp5`
- 트래픽 패턴 파악 없이 안전하게 온디맨드로 설정한 것으로 추정
- 실제로는 사용량이 완전히 일정하므로 프로비저닝 모드가 적합

## 3. 권장 조치

### 조치 1: `dynamodb-table-mnrimh` 용량 우축소 + Auto Scaling 적용

| 항목 | 현재 | 권장 (최소) | 권장 (최대) |
|------|------|------------|------------|
| RCU | 5,000 (고정) | 50 | 200 |
| WCU | 1,000 (고정) | 50 | 200 |

- 최대 사용량 100 기준, 최소 50 / 최대 200으로 Auto Scaling 설정 (목표 사용률 70%)
- 피크 대비 2배 마진 확보로 안정성 유지

### 조치 2: `dynamodb-table-wt6cp5` 온디맨드 → 프로비저닝 전환

- 사용량이 완전히 일정(std=0)하므로 프로비저닝 + Auto Scaling 전환
- RCU 50~200, WCU 50~200 범위로 Auto Scaling 적용

## 5. 전체 요약 (경영진 보고용)

TrackPulse의 DynamoDB 인프라에서 **심각한 과다 프로비저닝**이 발견되었습니다.

- 핵심 테이블 `mnrimh`의 읽기/쓰기 용량이 실제 사용량 대비 **50배/10배** 과다 설정
- 또 다른 테이블 `wt6cp5`는 안정적 트래픽임에도 비싼 온디맨드 모드 사용

**Auto Scaling 적용과 용량 우축소**를 통해 **월 약 $1,000 (연 $12,000)** 절감이 가능하며, 서비스 안정성에는 영향이 없습니다. 사용량이 30일간 완전히 일정한 패턴이므로 리스크가 매우 낮은 최적화입니다.
