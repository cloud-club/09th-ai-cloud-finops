# L1-013 분석 보고서: TrackPulse RDS 비용 최적화

## 1. 문제 식별

### 과도한 백업 보존 기간 (Critical)
- **대상**: `db-instance-58k76l`, `db-instance-7u4t4b` (db.r5.xlarge, 500GB gp3 각각)
- **현재 설정**: `backup_retention_period = 35일`
- **문제**: AWS RDS 백업 스토리지는 할당 스토리지 크기까지 무료이나, 보존 기간이 길수록 전체 백업 용량이 할당 스토리지를 초과하여 추가 비용 발생
- **비용 영향**: 약 **$266/월** 추가 지출

### Graviton 미전환 (Medium)
- **대상**: 전체 3개 인스턴스 (r5 세대)
- **문제**: r5(Intel) 인스턴스를 사용 중이며, r6g(Graviton2)로 전환 시 동일 성능에서 ~20% 비용 절감 가능

## 2. 근본 원인 분석

### 백업 보존 기간
- 2개의 xlarge 인스턴스에 35일 백업 보존이 설정되어 있음
- 각 인스턴스는 500GB 스토리지 할당 → 매일 전체 스냅샷 기준으로 보존 기간 28일 초과분에 대해 추가 과금
- **산출 근거** (cost_report의 pricing_note):
  - `2 × 500GB × (28 extra days / 30) × $0.095/GB-month ≈ $266/월`
- 3번째 인스턴스(`db-instance-mv1qab`)는 `backup_retention_period = 7일`로 적정 수준

### 메트릭 데이터 근거

| 인스턴스 | 인스턴스 클래스 | CPU 평균 | CPU 최대 | CPU 추세 | 백업 보존 |
|----------|---------------|---------|---------|---------|----------|
| db-instance-58k76l | db.r5.xlarge | 44.1% | 73.3% | stable | 35일 |
| db-instance-7u4t4b | db.r5.xlarge | 43.6% | 71.8% | increasing | 35일 |
| db-instance-mv1qab | db.r5.large | 60.2% | 100.0% | stable | 7일 |

- xlarge 인스턴스들의 CPU 사용률은 ~44%로 인스턴스 크기 자체는 적정 (다운사이징 시 ~88%로 위험)
- mv1qab는 이미 피크 100%에 도달하므로 현재 크기 유지 또는 업사이징 검토 필요
- **핵심 낭비는 인스턴스 크기가 아닌 백업 보존 기간**에 있음

## 3. 권장 조치

### 조치 1: 백업 보존 기간 축소 (즉시 실행)
- `db-instance-58k76l`, `db-instance-7u4t4b`의 `backup_retention_period`를 **35일 → 7일**로 변경
- 규정 준수 요건이 있다면 별도 S3 버킷에 수동 스냅샷을 장기 보관하는 방식으로 대체 (비용 훨씬 저렴)
- **예상 절감: ~$266/월**

### 조치 2: Graviton(r6g) 마이그레이션 (계획 후 실행)
- r5 → r6g로 전환 (MySQL 8.0은 Graviton 완벽 지원)
- db.r5.xlarge ($0.48/hr) → db.r6g.xlarge ($0.3836/hr): 인스턴스당 ~$70/월 절감
- db.r5.large ($0.24/hr) → db.r6g.large ($0.1918/hr): ~$35/월 절감
- **예상 절감: ~$175/월**
- 유지보수 윈도우에서 스냅샷 복원 방식으로 마이그레이션

## 4. 월 절감액 추정

| 조치 | 월 절감액 | 난이도 |
|------|----------|--------|
| 백업 보존 기간 35일 → 7일 | $266 | 낮음 (설정 변경) |
| r5 → r6g Graviton 전환 | $175 | 중간 (마이그레이션 필요) |
| **합계** | **$441** | |

- 현재 RDS 월 비용: ~$407 (M-0 기준)
- 전체 월 클라우드 비용 대비 절감률: $441 / $2,460 ≈ **17.9%**

> 참고: 백업 비용 $266은 cost_report의 RDS 항목에 포함되지 않은 별도 과금일 수 있으며, 이 경우 총 비용 $2,460 외에 추가로 발생하는 비용임

## 5. 전체 요약

TrackPulse의 RDS 인프라에서 **과도한 백업 보존 기간(35일)**이 가장 큰 비용 낭비 요인입니다. 2개의 db.r5.xlarge 인스턴스(각 500GB)에 설정된 35일 백업이 월 약 $266의 불필요한 백업 스토리지 비용을 발생시키고 있습니다. 이를 업계 표준인 7일로 축소하면 즉시 절감 가능합니다. 추가로 Graviton(r6g) 인스턴스로 전환하면 월 $175를 더 절감할 수 있어, **총 월 $441(약 18%)의 비용 절감**이 가능합니다.
